# 혈압 마라톤 멀티플레이 서버

업로드한 `index_optimized_v7` 게임의 기존 WebSocket 프로토콜(`/ws`)에 맞춘 Node.js 서버입니다.

## 포함 기능
- 방 생성 / 코드 입장 / 빠른 매치 / 준비 / 방장 시작 / 퇴장
- 최대 8명 방
- 서버 권한 이동 시뮬레이션(30Hz), 스냅샷 전송(15Hz)
- 클라이언트 입력 전송 제한(게임 클라이언트의 20Hz 입력과 호환)
- 입력 범위 검증, 입력 타임아웃, 공격/스킬의 서버 판정
- `/health` 상태 확인, `net:ping` RTT 측정
- WebSocket 압축 비활성화로 작은 실시간 패킷의 CPU 비용 절감

## Render 배포
1. 이 폴더를 GitHub 새 저장소에 업로드합니다.
2. Render에서 **New + → Web Service**를 선택하고 GitHub 저장소를 연결합니다.
3. Runtime: Node, Build Command: `npm install`, Start Command: `npm start`
4. 환경 변수 `NODE_VERSION=20` (필요하면) 설정 후 배포합니다.
5. Render의 `https://서비스이름.onrender.com/health`가 `{"ok":true,...}`를 반환하는지 확인합니다.
6. 게임 HTML 안의 `BUILT_IN_NET_SERVER_URL` 값을 해당 Render 주소로 바꿉니다. 예: `https://서비스이름.onrender.com`
7. 수정한 HTML을 itch.io에 다시 업로드합니다.

서버 주소는 게임 클라이언트가 `https://`를 자동으로 `wss://`로 바꾸고 `/ws`를 붙입니다.

## 로컬 실행
```bash
npm install
npm start
```
브라우저 게임 HTML은 `http://localhost` 또는 HTTPS로 호스팅하고, 서버는 `ws://localhost:3000/ws`를 사용합니다. itch.io의 HTTPS 게임 페이지는 반드시 배포된 HTTPS/WSS 서버에 연결해야 합니다.

## 핑과 성능에 관한 현실적인 안내
- 클라이언트는 이미 20Hz 입력 전송, 위치 보간, 로컬 예측 및 서버 보정을 수행합니다.
- 이 서버는 30Hz 시뮬레이션과 15Hz 스냅샷으로 부하를 제한합니다.
- WebSocket은 TCP 기반입니다. 브라우저 itch.io 빌드에서 일반 UDP 소켓을 직접 사용할 수 없으므로 이 구현은 WebSocket을 사용합니다. 인터넷 경로, 서버 지역, 무료 호스팅의 절전/콜드스타트, 사용자 Wi-Fi에 따른 핑 자체를 코드만으로 없앨 수는 없습니다.
- 무료 Render 인스턴스는 유휴 후 잠들 수 있어 첫 연결이 느릴 수 있습니다. 실제 상시 운영은 유료 상시 실행 인스턴스 또는 가까운 지역의 상시 서버를 권장합니다.
- 현재 서버 상태는 메모리에 저장됩니다. 서버 재시작 시 방이 사라집니다. 수평 확장/영속 방이 필요한 경우 Redis와 세션 재연결을 추가해야 합니다.

## 현재 구현의 범위
이 버전은 기존 클라이언트 프로토콜과 호환되는 플레이 가능한 기본 멀티플레이 서버입니다. 캐릭터별 전투 밸런스, 일부 스킬의 세부 효과, 포탑의 자동 공격/피격 판정은 원본 게임의 전체 로컬 전투 로직과 완전히 동일하다고 보장하지 않습니다. 실제 공개 전 두 브라우저로 테스트하고 전투 규칙을 추가 검증하세요.
